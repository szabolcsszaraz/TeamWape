4. GUEST NEEDS ARE GATED BY BUILDING REPAIR
======================================================================
Problem: the Pool's ServiceBuilding sits on the always-active Pool parent, so its Start()
unlocked the Relax need at game start although the pool was a ruin.

ServiceBuilding.cs changes:
    - Start(): finds BuildingRepair with GetComponentInParent. If the building is NOT repaired,
      the need is NOT unlocked; it subscribes to BuildingRepair.OnRepaired and unlocks then.
    - If BuildingLevelRequirements.UnlockNeedBeforeRepair is ON, it also listens to
      ResortUnlockManager.OnUnlockProgressChanged and unlocks the need as soon as the repair
      becomes available (MeetsWaveRequirement && MeetsResortLevelRequirement), even while ruined.
      Purpose: Ocean View demand starts at wave 6 to push the player to repair the Bungalow.
    - New: public bool IsOpenForGuests  (false while ruined).
    - Cleans up both subscriptions in OnDestroy.

ServiceNavigationTarget.cs: GetTargetsFor / FindNearest skip buildings where
    IsOpenForGuests is false, so tourists never walk into a ruin.

TouristServiceRoute.cs: when no open building serves a need it logs (not warns)
    "No open building serves Ocean View (missing or not repaired). Skipping." and the unit is
    abandoned (counts against satisfaction). This is intended behaviour before the Bungalow
    is repaired.

Resulting behaviour:
    waves 1-2 : no Relax, no Ocean View
    wave 3+   : Pool repair available; Relax unlocks only when the repair FINISHES
    wave 6+   : Bungalow repair available; Ocean View unlocks IMMEDIATELY (guests want it,
                go unserved until the Bungalow is repaired)

======================================================================
5. BUG FIX - BEACH BAR ICON SHOWED INACTIVE AT START
======================================================================
Cause: Awake/OnEnable order between GameObjects is undefined. The BeachBar's
ServiceStateVisual.OnEnable ran before ServiceBuilding.Awake counted its worker, saw
CanOperate == false and showed Inactive. The building's CurrentState stayed Normal, so
OnServiceStateChanged never fired to correct it. Moving the worker out and back forced
a real state change, which is why that "fixed" it.
Fix: ServiceStateVisual.Start() calls SyncWithServiceBuilding() once more (Start runs
after all Awake/OnEnable). Nothing else changed in that script.
